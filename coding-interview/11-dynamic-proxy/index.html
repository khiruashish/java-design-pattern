    11. Proxy: Caching & Lazy Loading¶

    L3 ★★★ · java.lang.reflect.Proxy, InvocationHandler, virtual proxy

    Problem¶

    Add result caching to any interface without writing a class per interface, and create an expensive service lazily, only when it's first used.

    See the pattern in motion¶

    Before you write any code, watch the pattern this problem is built on. Switch to Without it to see the bug the pattern prevents. Read the full Proxy page.

    Key idea¶

    A JDK dynamic proxy generates a class at run time that implements the interfaces you pass and routes every call to one InvocationHandler.invoke(proxy, method, args). That single handler can add caching, timing, security or transactions to any interface. Spring AOP and Mockito work this way. A virtual proxy holds a factory and builds the real object on first use. See Proxy.

    sequenceDiagram participant C as client participant P as $Proxy (generated) participant H as CachingHandler participant T as SlowCatalog C->>P: describe("A1") P->>H: invoke(method=describe, args=[A1]) H->>T: MISS → method.invoke(target) C->>P: describe("A1") P->>H: invoke(...) H-->>C: HIT → cached value

    Solution¶

    DynamicProxy.java
    import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;
import java.util.*;

/** Problem: add caching and timing to ANY interface without writing a class per interface (JDK dynamic proxy). */
public class DynamicProxy {

    interface ProductCatalog {
        String describe(String sku);
        int stock(String sku);
    }

    static final class SlowCatalog implements ProductCatalog {
        int calls;
        public String describe(String sku) { calls++; return "Product " + sku; }
        public int stock(String sku) { calls++; return sku.length(); }
    }

    /** One handler works for every interface: caches results by (method, args). */
    static final class CachingHandler implements InvocationHandler {
        private final Object target;
        private final Map<List<Object>, Object> cache = new HashMap<>();
        final List<String> log = new ArrayList<>();

        CachingHandler(Object target) { this.target = target; }

        @Override
        public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
            if (method.getDeclaringClass() == Object.class) return method.invoke(target, args);   // equals/hashCode/toString
            List<Object> key = new ArrayList<>();
            key.add(method.getName());
            if (args != null) key.addAll(Arrays.asList(args));
            if (cache.containsKey(key)) { log.add("HIT  " + key); return cache.get(key); }
            Object result = method.invoke(target, args);
            cache.put(key, result);
            log.add("MISS " + key);
            return result;
        }
    }

    @SuppressWarnings("unchecked")
    static <T> T caching(Class<T> type, T target, CachingHandler handler) {
        return (T) Proxy.newProxyInstance(type.getClassLoader(), new Class<?>[]{type}, handler);
    }

    /** Lazy (virtual) proxy: the expensive object is created on first use only. */
    static final class LazyCatalog implements ProductCatalog {
        private final java.util.function.Supplier<ProductCatalog> factory;
        private ProductCatalog real;
        LazyCatalog(java.util.function.Supplier<ProductCatalog> factory) { this.factory = factory; }
        private ProductCatalog real() { if (real == null) real = factory.get(); return real; }
        public String describe(String sku) { return real().describe(sku); }
        public int stock(String sku) { return real().stock(sku); }
        boolean initialised() { return real != null; }
    }

    public static void main(String[] args) {
        SlowCatalog slow = new SlowCatalog();
        CachingHandler handler = new CachingHandler(slow);
        ProductCatalog catalog = caching(ProductCatalog.class, slow, handler);

        catalog.describe("A1"); catalog.describe("A1"); catalog.stock("A1"); catalog.stock("A1"); catalog.describe("B2");
        handler.log.forEach(System.out::println);
        System.out.println("real calls = " + slow.calls + " (5 requests)");
        System.out.println("proxy class = " + (Proxy.isProxyClass(catalog.getClass()) ? "generated $Proxy" : "?"));
        check(slow.calls == 3, "two hits served from cache");

        LazyCatalog lazy = new LazyCatalog(SlowCatalog::new);
        System.out.println("lazy created? " + lazy.initialised());
        lazy.stock("X");
        System.out.println("after first call, created? " + lazy.initialised());
        check(lazy.initialised(), "lazy init");
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    Proxy.newProxyInstance(loader, new Class<?>[]{type}, handler) This generates a class implementing type. It works for interfaces only; class proxies need ByteBuddy or CGLIB, which is what Spring uses for @Configuration.
    if (method.getDeclaringClass() == Object.class) return method.invoke(target, args) equals, hashCode and toString are also routed through the handler, so don't cache them.
    List<Object> key = [methodName, args...] A cache key built from method plus arguments. List.equals and hashCode make it a valid map key.
    method.invoke(target, args) Reflective call to the real object. In production, unwrap InvocationTargetException so callers see the original exception.
    private ProductCatalog real() { if (real == null) real = factory.get(); ... } Virtual proxy: lazy creation. This version isn't thread-safe; use a holder or a lock if the proxy is shared.

    Complexity¶

    Approach Time Space
    cached call O(args) to build the key O(distinct calls)

    Run it¶

HIT  [describe, A1]
MISS [stock, A1]
HIT  [stock, A1]
MISS [describe, B2]

proxy class = generated $Proxy
lazy created? false
after first call, created? true
PASS

    Common mistakes¶

    • Expecting a JDK proxy to work on a concrete class. It only implements interfaces.
    • Self-invocation: inside the target, this.otherMethod() bypasses the proxy. That's the classic "@Transactional doesn't work" bug in Spring.
    • Caching methods with side effects, or with mutable arguments used as keys.

    Follow-up questions¶

    Why doesn't @Transactional work when a method calls another method in the same class?

    Spring applies @Transactional with a proxy around the bean. A call from inside the bean (this.save()) goes straight to the target and skips the proxy, so no transaction starts. Fix it by moving the method to another bean, injecting the bean's own proxy, or using AspectJ weaving.

    JDK proxy vs CGLIB/ByteBuddy?

    JDK proxies implement interfaces, using built-in reflection. CGLIB and ByteBuddy subclass the target class at run time, so they work without interfaces, but they can't proxy final classes or methods. Spring Boot defaults to class-based proxies.
