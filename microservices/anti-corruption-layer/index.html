    Intermediate Microservices Migration

    Anti-Corruption Layer (ACL)¶

    🟡 Intermediate Microservices Interview frequency ⭐⭐⭐⭐

    TL;DR

    An anti-corruption layer is a translation boundary between your domain model and an external or legacy system with a different model. It converts their data, codes and protocols into your concepts (and back), so their quirks never leak into your code. It's the Adapter and Facade patterns applied at the scale of whole systems (a Domain-Driven Design strategic pattern).

    1. Intent & Problem It Solves¶

    The problem in plain English: the new catalog service reads products from a 25-year-old ERP: fields like MAT_NO with 18-digit zero padding, prices as "1.299,00", units KGM/ST, and DEL_FLAG = "X" for inactive. If those details spread through the new code, the new service becomes as hard to change as the ERP, and replacing the ERP later means touching everything. That's the "corruption".

    Definition (Eric Evans, Domain-Driven Design):

    Create an isolating layer to provide clients with functionality in terms of their own domain model. The layer talks to the other system through its existing interface, requiring little or no modification to the other system.

    Typical ACL building blocks:

    Part Role
    Facade Simplifies the foreign system's API (many calls → one)
    Adapter Talks the foreign protocol (SOAP, XML, fixed-width files, RFC)
    Translator Maps foreign data and codes to domain objects, and back

    2. Real-World Analogy¶

    An interpreter and customs desk at a border

    Travellers (data) from another country arrive with their own language, units and documents. At the border they're translated and checked: miles become kilometres, unknown items are held for inspection. Inside the country, nobody has to speak the foreign language.

    3. Structure¶

    flowchart LR
    subgraph Ours["Our bounded context"]
      D[Domain services] --> P[Port: ProductCatalog]
    end
    P --> ACL[Anti-corruption layer<br/>facade + adapter + translator]
    ACL --> L[Legacy ERP / partner API<br/>foreign model]
    Participant Responsibility
    Our domain Uses only its own types (Product, Money, Unit)
    ACL Calls the foreign system; translates in both directions; rejects or flags what can't be mapped
    Foreign system Unchanged; often not under our control

    4. Naive Approach (Without the Pattern)¶

    // Deep inside the pricing service...
if ("X".equals(row.get("DEL_FLAG")) || row.get("BASE_UOM").equals("ST")) { ... }
BigDecimal price = new BigDecimal(row.get("PRICE").replace(".", "").replace(",", "."));
// ...repeated in cart, search and recommendations. Replacing the ERP = rewriting all of them.

    5. Three Real-World Examples¶

    Example 1: Products from a Legacy ERP (Grocery)¶

    Scenario: The catalog service needs product data from the ERP's material master. The ACL zero-pads SKUs for the ERP, strips padding on the way back, title-cases descriptions, maps unit codes to an enum, parses European-format prices into paise, and turns DEL_FLAG into a boolean. Unknown materials become Optional.empty().

    Full Code:

    package com.handbook.microservices.acl.erp;

import java.math.BigDecimal;
import java.util.Map;
import java.util.Optional;

/**
 * The anti-corruption layer between our catalog and a decades-old ERP. The ERP's cryptic fields,
 * zero-padded codes, comma decimals and status flags stop here; the rest of our code only sees
 * our own Product model.
 */
public final class ErpProductTranslator {

    public enum Unit { KILOGRAM, PIECE, LITRE }

    /** Our domain model: clean names, types and invariants. */
    public record Product(String sku, String name, Unit unit, long pricePaise, boolean active) {
    }

    /** The ERP's interface, as it is. We don't control it. */
    public interface LegacyErp {
        Map<String, String> readMaterial(String materialNumber);
    }

    private final LegacyErp erp;

    public ErpProductTranslator(LegacyErp erp) {
        this.erp = erp;
    }

    public Optional<Product> product(String sku) {
        Map<String, String> raw = erp.readMaterial(String.format("%018d", Long.parseLong(sku.replace("SKU-", "")))); // (1)!
        if (raw.isEmpty()) {
            return Optional.empty();
        }
        return Optional.of(new Product(
                "SKU-" + Long.parseLong(raw.get("MAT_NO")),       // strip the zero padding
                titleCase(raw.get("MAT_DESC").trim()),
                unit(raw.get("BASE_UOM")),                       // (2)!
                new BigDecimal(raw.get("PRICE").replace(".", "").replace(',', '.'))
                        .movePointRight(2).longValueExact(),     // (3)!
                !"X".equals(raw.get("DEL_FLAG"))));              // (4)!
    }

    private static Unit unit(String erpCode) {
        return switch (erpCode) {
            case "KGM" -> Unit.KILOGRAM;
            case "ST", "PCE" -> Unit.PIECE;
            case "LTR" -> Unit.LITRE;
            default -> throw new IllegalArgumentException("unmapped ERP unit " + erpCode);
        };
    }

    private static String titleCase(String upper) {
        StringBuilder sb = new StringBuilder();
        for (String w : upper.toLowerCase().split(" ")) {
            sb.append(Character.toUpperCase(w.charAt(0))).append(w.substring(1)).append(' ');
        }
        return sb.toString().trim();
    }
}
    1. Our SKU format → the ERP's 18-digit, zero-padded material number. The ERP's key format never leaves the ACL.
    2. Explicit code mapping; an unmapped unit fails loudly instead of silently becoming wrong data.
    3. "1.299,00" (thousands dot, decimal comma) → 129900 paise, with exact decimal arithmetic.
    4. The ERP's soft-delete flag becomes a meaningful domain property.
    package com.handbook.microservices.acl.erp;

import java.util.Map;
import java.util.TreeMap;

public class ErpAclDemo {

    public static void main(String[] args) {
        ErpProductTranslator.LegacyErp erp = materialNumber -> switch (materialNumber) {
            case "000000000000012345" -> Map.of("MAT_NO", "000000000000012345", "MAT_DESC", "ALPHONSO MANGO PREMIUM   ",
                    "BASE_UOM", "KGM", "PRICE", "1.299,00", "DEL_FLAG", "");
            case "000000000000012346" -> Map.of("MAT_NO", "000000000000012346", "MAT_DESC", "COCONUT WATER",
                    "BASE_UOM", "LTR", "PRICE", "89,50", "DEL_FLAG", "X");
            default -> Map.of();
        };
        var catalog = new ErpProductTranslator(erp);

        System.out.println("=== Grocery: reading products from a legacy ERP through an ACL ===");
        System.out.println("ERP says   : " + new TreeMap<>(erp.readMaterial("000000000000012345")));
        System.out.println("We see     : " + catalog.product("SKU-12345").orElseThrow());
        System.out.println("We see     : " + catalog.product("SKU-12346").orElseThrow());
        System.out.println("Unknown SKU: " + catalog.product("SKU-99999"));
    }
}

    Output:

    === Grocery: reading products from a legacy ERP through an ACL ===
ERP says   : {BASE_UOM=KGM, DEL_FLAG=, MAT_DESC=ALPHONSO MANGO PREMIUM   , MAT_NO=000000000000012345, PRICE=1.299,00}
We see     : Product[sku=SKU-12345, name=Alphonso Mango Premium, unit=KILOGRAM, pricePaise=129900, active=true]
We see     : Product[sku=SKU-12346, name=Coconut Water, unit=LITRE, pricePaise=8950, active=false]
Unknown SKU: Optional.empty

    Why an ACL here:

    • The ERP's conventions are confined to one class with focused tests.
    • Replacing the ERP later means writing a new translator, not changing the catalog domain.

    Example 2: Policies from Legacy XML (Insurance)¶

    Scenario: The new claims service needs policy data from a legacy policy-admin system that returns XML with tags like POL_REF, CVR_CD, EXP_DT (yyyyMMdd). The ACL parses it securely (no external entities), maps cover codes to an enum, converts dates, and produces a Policy with behaviour (coversOn(date)). Unknown cover codes are rejected at the boundary.

    Full Code:

    package com.handbook.microservices.acl.insurance;

import org.w3c.dom.Document;
import org.w3c.dom.Element;
import org.w3c.dom.NodeList;

import javax.xml.XMLConstants;
import javax.xml.parsers.DocumentBuilderFactory;
import java.io.ByteArrayInputStream;
import java.nio.charset.StandardCharsets;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.util.ArrayList;
import java.util.List;

/**
 * Translates the legacy policy-admin system's XML (its own vocabulary, date format and codes)
 * into our claims service's Policy model. Only this class knows the XML exists.
 */
public final class PolicyXmlTranslator {

    public enum CoverType { COMPREHENSIVE, THIRD_PARTY }

    public record Policy(String number, String holder, CoverType cover, LocalDate validUntil, List<String> namedDrivers) {
        public boolean coversOn(LocalDate date) {
            return !date.isAfter(validUntil);
        }
    }

    private static final DateTimeFormatter LEGACY_DATE = DateTimeFormatter.ofPattern("yyyyMMdd");

    public Policy translate(String xml) {
        try {
            DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
            factory.setFeature(XMLConstants.FEATURE_SECURE_PROCESSING, true); // (1)!
            factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
            Document doc = factory.newDocumentBuilder()
                    .parse(new ByteArrayInputStream(xml.getBytes(StandardCharsets.UTF_8)));
            Element root = doc.getDocumentElement();
            List<String> drivers = new ArrayList<>();
            NodeList nodes = root.getElementsByTagName("DRV_NM");
            for (int i = 0; i < nodes.getLength(); i++) {
                drivers.add(nodes.item(i).getTextContent().trim());
            }
            return new Policy(
                    text(root, "POL_REF").replace("/", "-"),
                    text(root, "INS_NM"),
                    switch (text(root, "CVR_CD")) { // (2)!
                        case "01" -> CoverType.COMPREHENSIVE;
                        case "02" -> CoverType.THIRD_PARTY;
                        default -> throw new IllegalArgumentException("unknown cover code " + text(root, "CVR_CD"));
                    },
                    LocalDate.parse(text(root, "EXP_DT"), LEGACY_DATE), // (3)!
                    List.copyOf(drivers));
        } catch (Exception e) {
            throw new IllegalArgumentException("cannot translate policy XML: " + e.getMessage(), e);
        }
    }

    private static String text(Element root, String tag) {
        return root.getElementsByTagName(tag).item(0).getTextContent().trim();
    }
}
    1. Secure XML parsing: disallow DOCTYPE/external entities (XXE attacks). The boundary is also a security boundary.
    2. Codes → domain enum; anything unknown is an error, not a guess.
    3. Legacy date format converted once into LocalDate.
    package com.handbook.microservices.acl.insurance;

import java.time.LocalDate;

public class PolicyAclDemo {

    public static void main(String[] args) {
        String legacyXml = """
                <PLCY_RSP>
                  <POL_REF>MTR/2025/004417</POL_REF>
                  <INS_NM>Ravi Kumar</INS_NM>
                  <CVR_CD>01</CVR_CD>
                  <EXP_DT>20261231</EXP_DT>
                  <DRVRS><DRV_NM>Ravi Kumar</DRV_NM><DRV_NM>Anita Kumar</DRV_NM></DRVRS>
                </PLCY_RSP>
                """;
        var translator = new PolicyXmlTranslator();

        System.out.println("=== Insurance: claims service reads policies from a legacy XML system ===");
        var policy = translator.translate(legacyXml);
        System.out.println("Policy: " + policy);
        System.out.println("Accident on 2026-11-02 covered? " + policy.coversOn(LocalDate.of(2026, 11, 2)));
        System.out.println("Accident on 2027-01-05 covered? " + policy.coversOn(LocalDate.of(2027, 1, 5)));
        try {
            translator.translate(legacyXml.replace("<CVR_CD>01", "<CVR_CD>07"));
        } catch (IllegalArgumentException e) {
            System.out.println("Unknown code rejected at the boundary: " + e.getMessage());
        }
    }
}

    Output:

    === Insurance: claims service reads policies from a legacy XML system ===
Policy: Policy[number=MTR-2025-004417, holder=Ravi Kumar, cover=COMPREHENSIVE, validUntil=2026-12-31, namedDrivers=[Ravi Kumar, Anita Kumar]]
Accident on 2026-11-02 covered? true
Accident on 2027-01-05 covered? false
Unknown code rejected at the boundary: cannot translate policy XML: unknown cover code 07

    Why an ACL here:

    • The claims domain talks about Policy, CoverType and coverage dates, not XML tags.
    • Bad or unexpected data is stopped at the edge, where it's easy to log and investigate.

    Example 3: One Status Model for Many Carriers (Logistics)¶

    Scenario: Each delivery partner reports status in its own vocabulary: QuickDrop uses OFD/DL/NDR; BlueKite uses 1–4 and 9. A per-carrier mapping translates them into our ShipmentStatus. Inputs are normalized ("dl " → DL). An unmapped code becomes UNKNOWN with an alert, instead of crashing the tracking pipeline.

    Full Code:

    package com.handbook.microservices.acl.logistics;

import java.util.Map;

/**
 * Each delivery partner reports status in its own vocabulary. One adapter per partner maps it to
 * OUR status model; unknown codes become UNKNOWN (and an alert) instead of crashing the pipeline.
 */
public final class CarrierStatusTranslator {

    public enum ShipmentStatus { PICKED_UP, IN_TRANSIT, OUT_FOR_DELIVERY, DELIVERED, FAILED_ATTEMPT, UNKNOWN }

    public record CarrierEvent(String carrier, String awb, String rawStatus) {
    }

    public record TrackingUpdate(String trackingId, ShipmentStatus status) {
    }

    private static final Map<String, Map<String, ShipmentStatus>> MAPPINGS = Map.of( // (1)!
            "QuickDrop", Map.of("PU", ShipmentStatus.PICKED_UP, "IT", ShipmentStatus.IN_TRANSIT,
                    "OFD", ShipmentStatus.OUT_FOR_DELIVERY, "DL", ShipmentStatus.DELIVERED,
                    "NDR", ShipmentStatus.FAILED_ATTEMPT),
            "BlueKite", Map.of("1", ShipmentStatus.PICKED_UP, "2", ShipmentStatus.IN_TRANSIT,
                    "3", ShipmentStatus.OUT_FOR_DELIVERY, "4", ShipmentStatus.DELIVERED,
                    "9", ShipmentStatus.FAILED_ATTEMPT));

    public TrackingUpdate translate(CarrierEvent event) {
        ShipmentStatus status = MAPPINGS.getOrDefault(event.carrier(), Map.of())
                .getOrDefault(event.rawStatus().trim().toUpperCase(), ShipmentStatus.UNKNOWN); // (2)!
        if (status == ShipmentStatus.UNKNOWN) {
            System.out.println("    ALERT: unmapped status '" + event.rawStatus() + "' from " + event.carrier());
        }
        return new TrackingUpdate(event.carrier() + ":" + event.awb(), status); // (3)!
    }
}
    1. Mappings are data, one table per partner. Onboarding a new carrier means adding a mapping, not changing domain code.
    2. Normalize, then map; unknown codes get a safe default plus an alert, because a tracking page showing "unknown" beats a stopped pipeline.
    3. Our own tracking ID scheme, independent of each carrier's AWB format.
    package com.handbook.microservices.acl.logistics;

import com.handbook.microservices.acl.logistics.CarrierStatusTranslator.CarrierEvent;

import java.util.List;

public class CarrierAclDemo {

    public static void main(String[] args) {
        var acl = new CarrierStatusTranslator();
        System.out.println("=== Logistics: two carriers, one status model ===");
        for (CarrierEvent e : List.of(
                new CarrierEvent("QuickDrop", "771020", "OFD"),
                new CarrierEvent("BlueKite", "BK-55", "3"),
                new CarrierEvent("QuickDrop", "771020", "dl "),
                new CarrierEvent("BlueKite", "BK-56", "9"),
                new CarrierEvent("BlueKite", "BK-57", "7"))) {
            System.out.printf("%-9s %-7s %-4s -> %s%n", e.carrier(), e.awb(), "'" + e.rawStatus() + "'", acl.translate(e));
        }
    }
}

    Output:

    === Logistics: two carriers, one status model ===
QuickDrop 771020  'OFD' -> TrackingUpdate[trackingId=QuickDrop:771020, status=OUT_FOR_DELIVERY]
BlueKite  BK-55   '3'  -> TrackingUpdate[trackingId=BlueKite:BK-55, status=OUT_FOR_DELIVERY]
QuickDrop 771020  'dl ' -> TrackingUpdate[trackingId=QuickDrop:771020, status=DELIVERED]
BlueKite  BK-56   '9'  -> TrackingUpdate[trackingId=BlueKite:BK-56, status=FAILED_ATTEMPT]
    ALERT: unmapped status '7' from BlueKite
BlueKite  BK-57   '7'  -> TrackingUpdate[trackingId=BlueKite:BK-57, status=UNKNOWN]

    Why an ACL here:

    • Many external models, one internal model; the rest of the system never learns about carriers' codes.
    • Fail-soft vs. fail-hard is a deliberate choice per boundary (insurance codes: reject; tracking codes: flag).
    Unit Tests: AntiCorruptionLayerTest.java 
    package com.handbook.microservices;

import com.handbook.microservices.acl.erp.ErpProductTranslator;
import com.handbook.microservices.acl.erp.ErpProductTranslator.Unit;
import com.handbook.microservices.acl.logistics.CarrierStatusTranslator;
import com.handbook.microservices.acl.logistics.CarrierStatusTranslator.CarrierEvent;
import com.handbook.microservices.acl.logistics.CarrierStatusTranslator.ShipmentStatus;
import com.handbook.microservices.acl.outbound.LegacyOrderExporter;
import com.handbook.microservices.acl.outbound.LegacyOrderExporter.OrderLine;
import org.junit.jupiter.api.Test;

import java.time.LocalDate;
import java.util.Map;

import static org.assertj.core.api.Assertions.assertThat;

class AntiCorruptionLayerTest {

    @Test
    void erpFieldsAreTranslatedIntoDomainTypes() {
        var acl = new ErpProductTranslator(n -> Map.of("MAT_NO", n, "MAT_DESC", "RICE", "BASE_UOM", "ST",
                "PRICE", "1.000,50", "DEL_FLAG", ""));
        var p = acl.product("SKU-7").orElseThrow();
        assertThat(p.sku()).isEqualTo("SKU-7");
        assertThat(p.unit()).isEqualTo(Unit.PIECE);
        assertThat(p.pricePaise()).isEqualTo(100_050);
        assertThat(p.active()).isTrue();
    }

    @Test
    void unknownCarrierCodesBecomeUnknown() {
        var update = new CarrierStatusTranslator().translate(new CarrierEvent("BlueKite", "1", "42"));
        assertThat(update.status()).isEqualTo(ShipmentStatus.UNKNOWN);
    }

    @Test
    void fixedWidthRecordsHaveExactLength() {
        String r = LegacyOrderExporter.toRecord(new OrderLine("O-1", "Élodie", 3, LocalDate.of(2026, 1, 2)));
        assertThat(r).hasSize(41).contains("ELODIE").endsWith("00003260102");
    }
}

    6. Variations & Modern Java Take¶

    • Ports and adapters: define a port in your domain (ProductCatalog), and implement it in the ACL. See Hexagonal Architecture.
    • ACL as a separate service: when several services need the same legacy system, an "integration service" owns the translation (and caching) once.
    • Mapping libraries: MapStruct generates compile-time mappers for the boring field-to-field part; keep code mappings and rules explicit.
    • Event translation: translate legacy events (CDC rows, IDocs, flat files) into clean domain events before publishing to your event bus.
    • Contract tests: record real responses from the foreign system and test the translator against them.

    7. Where It Lives in Real Frameworks¶

    Where Anti-corruption layer
    DDD context maps "ACL" relationship between bounded contexts
    Apache Camel / Spring Integration Message translators, content enrichers, normalizers (EIP)
    SAP Integration Suite, MuleSoft Integration platforms often acting as ACLs
    MapStruct Generated mappers inside ACL code
    Strangler migrations ACL between new services and the old system

    8. Pros, Cons & Trade-offs¶

    ✅ Pros ❌ Cons
    Domain model stays clean and independent Extra layer to build and maintain
    Foreign system can be replaced behind it Translation adds latency and possibly caching complexity
    One place for validation, security and logging of foreign data Can become a bottleneck if one team owns all ACLs
    Easy to test with recorded responses Mapping gaps discovered only with real data

    9. Pitfalls & Anti-Patterns¶

    Leaky ACL

    Returning the foreign DTO "for now" or adding getRawField() lets foreign concepts creep back into the domain. The ACL's public API must use only your types.

    Silent defaults

    Mapping unknown codes to a plausible value ("07" → COMPREHENSIVE) creates wrong data that surfaces months later. Fail loudly, or map to an explicit UNKNOWN plus an alert.

    Business logic in the translator

    The ACL translates and validates the shape of data. Business rules (is this claim payable?) belong in the domain.

    No tests against real samples

    Legacy systems have edge cases nobody documented. Build a corpus of real (anonymized) messages and run the translator against all of them in CI.

    10. Senior / Architect Deep Dive (10–15 yrs)¶

    Context mapping. In DDD terms, use an ACL when you're downstream of a model you can't influence (legacy, vendor, partner) and don't want to conform. If the upstream offers a well-designed Open Host Service / Published Language, a thinner ACL may suffice; if both teams cooperate closely, a shared kernel or partnership might be better.

    ACL in migrations. During a strangler migration, the ACL lets new services use the legacy system's data in new terms. When the legacy capability is replaced, only the ACL's implementation changes.

    Ownership and scaling. Per-service ACLs keep autonomy; a shared integration service avoids duplicating complex legacy access (connection limits, licensing, caching). Choose based on how many consumers there are and how complex the access is.

    Production checklist¶

    • ACL API exposes only domain types; foreign DTOs never escape.
    • Explicit mappings for codes and units; unknowns fail or are flagged deliberately.
    • Secure parsing (XXE-safe XML, size limits), input validation, logging of rejected records.
    • Translator tests against a corpus of real samples; contract tests with the foreign system.
    • Timeouts, retries and caching for calls to the foreign system.
    • Metrics for translation failures and unknown codes.

    Explain it in 2 minutes (system design round)¶

    "Our new services integrate with the legacy ERP and with carrier APIs through anti-corruption layers. Each ACL exposes a port in our domain language, like ProductCatalog.product(sku) or TrackingUpdate, and inside does the protocol calls, field and code mappings, unit and currency conversion, and validation. Unknown codes are rejected or flagged depending on the risk. Translators are tested against recorded real messages. When we retire the ERP, we replace the ACL implementation; nothing in the domain changes."

    War story: the unit that cost a fortune

    A retailer's replenishment service read ERP order quantities directly. One supplier's materials used unit CS (case of 24) instead of ST (piece). The code assumed pieces everywhere. A store ordered "12" bottles of oil and received 12 cases (288 bottles), for weeks, across 80 stores, before anyone noticed the overstock. Fix: an ACL that converts all ERP quantities into base units with explicit conversion factors, rejecting unknown units; a report of rejected records reviewed daily. Lesson: foreign units and codes are where silent, expensive errors live. Translate them explicitly, once.

    12. Interview Corner¶

    Q1. What is an anti-corruption layer?

    A translation layer between our system and an external/legacy system, so the external model doesn't leak into our code.

    Q2. Which design patterns does an ACL use?

    Adapter (protocol/interface), Facade (simplify), and translators/mappers (data and codes).

    Q3. Give an example.

    Converting a legacy ERP's MAT_NO, KGM and "1.299,00" into our Product(sku, unit=KILOGRAM, pricePaise=129900).

    Q4. Why not just use the legacy data directly?

    Its conventions would spread everywhere, making our code hard to change and the legacy system hard to replace.

    Q5. Where is it used in microservices migrations?

    Between new services and the old monolith/ERP during a strangler-fig migration.

    Q1. How do you handle unknown values from the foreign system?

    Decide per boundary: reject (with logging and alerts) for risky data, or map to an explicit UNKNOWN for non-critical data. Never guess silently.

    Q2. ACL vs. adapter?

    An adapter converts one interface; an ACL protects a whole domain model, combining adapters, facades and translators at a system boundary.

    Q3. How do you test an ACL?

    Unit tests with recorded real responses (including edge cases), contract tests against the foreign system, and property tests for conversions.

    Q4. Should the ACL be its own service?

    If many services need the same legacy system (or access is complex/licensed), yes; otherwise, a module in each consuming service keeps autonomy.

    Q5. Is MapStruct enough for an ACL?

    It helps with field mapping, but code tables, unit conversions, validation and protocol handling need explicit code.

    Q1. "When do you use an ACL vs. conforming to the upstream model?"

    Conform when the upstream model is good and stable (and you're happy to depend on it); use an ACL when it's legacy, poorly fitting or likely to be replaced, or controlled by another organization.

    Q2. "Design integration between new microservices and SAP ECC during a migration."

    ACL/integration services exposing domain APIs and events; reads via BAPIs/OData or CDC; writes via official interfaces (IDocs/BAPIs); translation of codes and units; caching; monitoring of rejected records; ACL implementations swapped as capabilities move to S/4HANA or new services.

    Q3. "How do you keep many ACLs consistent across teams?"

    Shared libraries for common mappings (units, currencies), a canonical event schema for integration events, and contract tests, while keeping each team's domain model their own.

    Q4. "What security concerns belong at the ACL?"

    Input validation, safe parsers (XXE, deserialization), size limits, authentication to the foreign system, and data minimization (don't import fields you don't need, especially PII).

    Q5. "An ACL adds 80 ms per call to a slow legacy API. Options?"

    Cache reference data, batch requests, replicate via CDC into a local read model, or call asynchronously where the use case allows.

    Problem: The ACL works in both directions. The warehouse system only accepts orders as fixed-width records: 10-char order number, 20-char upper-case name without accents, a 5-digit zero-padded quantity, and a yyMMdd date. Translate our OrderLines and guarantee every record is exactly 41 characters.

    Solution 
    package com.handbook.microservices.acl.outbound;

import java.text.Normalizer;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.util.List;

/**
 * Coding challenge: the ACL works in both directions. The warehouse system only accepts orders as
 * fixed-width records: 10-char order number, 20-char customer name (upper case, no accents),
 * quantity right-aligned in 5 digits, and a YYMMDD date. Translate our Order into that format.
 */
public final class LegacyOrderExporter {

    public record OrderLine(String orderId, String customerName, int quantity, LocalDate date) {
    }

    public static String toRecord(OrderLine o) {
        String id = o.orderId().replace("-", "");
        String name = Normalizer.normalize(o.customerName(), Normalizer.Form.NFD)
                .replaceAll("\\p{M}", "").toUpperCase();
        if (o.quantity() < 0 || o.quantity() > 99_999) {
            throw new IllegalArgumentException("quantity does not fit in 5 digits: " + o.quantity());
        }
        return pad(id, 10) + pad(name, 20) + String.format("%05d", o.quantity())
                + o.date().format(DateTimeFormatter.ofPattern("yyMMdd"));
    }

    private static String pad(String s, int width) {
        return s.length() >= width ? s.substring(0, width) : s + " ".repeat(width - s.length());
    }

    public static List<String> export(List<OrderLine> orders) {
        return orders.stream().map(LegacyOrderExporter::toRecord).toList();
    }
}

    package com.handbook.microservices.acl.outbound;

import com.handbook.microservices.acl.outbound.LegacyOrderExporter.OrderLine;

import java.time.LocalDate;
import java.util.List;

public class LegacyExportDemo {

    public static void main(String[] args) {
        System.out.println("=== Challenge: outbound translation to a fixed-width legacy format ===");
        List<String> records = LegacyOrderExporter.export(List.of(
                new OrderLine("ORD-1", "Asha Rao", 2, LocalDate.of(2026, 10, 13)),
                new OrderLine("ORD-12345678901", "Zoë Fernandes-D'Souza", 12, LocalDate.of(2026, 10, 13))));
        System.out.println("|" + "0123456789".repeat(5).substring(0, 41) + "|");
        records.forEach(r -> System.out.println("|" + r + "|"));
        System.out.println("Every record is 41 characters: " + records.stream().allMatch(r -> r.length() == 41));
    }
}

    Key points to say: Normalizer + removing combining marks turns "Zoë" into "ZOE"; truncate and pad to exact widths; validate values that can't fit (quantity over 99,999) instead of corrupting the record; test the exact length.

    13. Quick Revision Card¶

    Remember in 30 seconds

    • Translate at the boundary; the domain sees only its own types.
    • Facade + adapter + translator, at system scale (DDD).
    • Explicit code/unit mappings; unknowns rejected or flagged, never guessed.
    • Secure parsing and validation at the edge.
    • Makes the legacy system replaceable.
