=== Ride-hailing: 'trip-events' (6 partitions) and a Scaling Consumer Group ===
pod-1 joins -> {pod-1=[0, 1, 2, 3, 4, 5]}
pod-2 joins -> {pod-1=[0, 1, 2], pod-2=[3, 4, 5]}
pod-3 joins -> {pod-1=[0, 1], pod-2=[2, 3], pod-3=[4, 5]}
pod-7 joins -> {pod-1=[0], pod-2=[1], pod-3=[2], pod-4=[3], pod-5=[4], pod-6=[5], pod-7=[]}  <- more consumers than partitions: one idles
pod-2 dies  -> {pod-1=[0], pod-3=[1], pod-4=[2], pod-5=[3], pod-6=[4], pod-7=[5]}
Trip TRIP-88 always goes to partition 2, so its events are processed in order by whoever owns it.
